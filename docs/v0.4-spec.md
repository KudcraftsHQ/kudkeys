# Kud Keys v0.4 — sync and automatic backup

Hammas wants his keyboard settings and learned words **in the database**, **synced** between the server and
the phone, and **backed up automatically**. Builds on v0.3 (branch `v0.4` starts from `v0.3`). Working rules
from `docs/v0.1-spec.md` still apply.

## What gets synced

1. **Settings** — the app's SharedPreferences as JSON (HeliBoard's `settingsToJsonStream` format), **excluding**
   anything secret or device-bound: the session/legacy token, voice server URL, the voice draft, account
   state, sync bookkeeping, and per-device sizes (keyboard height/padding scales stay per device). Last writer
   wins per key, by the device's `updatedAt`.
2. **Words** — the words Kud Keys knows Hammas uses, as rows `{word, locale, count, source, deleted, updatedAt}`.
   `source`: `typed` (learned on the phone from user history), `swiftkey` (imported), `manual` (added on the
   web/app). Merge rule: union by `(word, locale)`; `count = max`; a delete is a tombstone that wins over an
   older add. Never learned from private fields (already true on the phone).
3. **Backups** — the full HeliBoard backup zip (learned-word dictionary files + user-added dictionaries + prefs
   JSON, minus the secrets above), uploaded as one blob. Exact restore of the phone's state.

## Phone (Android)

- **When signed in, sync runs:** right after sign-in (pull first, then push), when the settings screen
  closes after a change, and periodically with WorkManager (every 6 h, unmetered-or-any network, battery not
  low). "Sync now" in Account.
- **Push words:** read the user-history dictionaries (`ExpandableBinaryDictionary` word iteration —
  `getNextWordProperty`) for the enabled locales and send changed words since the last sync with their counts.
- **Pull words:** download all non-deleted words and write them into a **synced add-on dictionary** per locale
  (type `synced`, built on the device the way user-added dictionaries are stored: `synced_user.dict` in the
  locale's cache dir, through HeliBoard's own dictionary writing code or `DictionaryFacilitator` APIs — never
  the shared Android personal dictionary). That's how the 17k SwiftKey words reach the phone.
- **Removing a suggestion** (long-press in the suggestion strip → remove) also sends a tombstone.
- **Backup:** every 24 h (WorkManager, same constraints) and from "Back up now", build the HeliBoard backup zip
  without secrets and upload it. **Restore:** Account → Backups lists them (date, device, size); pick one →
  confirm → apply exactly like HeliBoard's restore, then re-sync.
- Account screen gets a **Sync** section: last synced / last backup time, Sync now, Back up now, Backups,
  "Automatic backup" switch (default on). Errors shown plainly; no sync when signed out.

## Server

Prisma models (names in the project's style):
- `KeyboardSettings` (userId unique, prefs Json, updatedAt, deviceId)
- `Word` (userId, word, locale, count Int, source, deleted Bool, updatedAt; unique (userId, word, locale))
- `Backup` (id, userId, createdAt, deviceId, deviceName, kind `auto|manual`, sizeBytes, sha256, data Bytes
  gzip; retention per user: keep the newest 14 daily + 8 weekly, prune on insert; max 20 MB each)

Endpoints (session token only; legacy tokens refused):
```
GET  /api/sync/settings                → { prefs, updatedAt } | 404
PUT  /api/sync/settings  { prefs, updatedAt, deviceId } → { prefs, updatedAt }   (merged result)

GET  /api/sync/words?since=<iso>       → { words: [{word,locale,count,source,deleted,updatedAt}], now }
POST /api/sync/words     { words: [...] (≤5000 per call) } → { accepted, now }
POST /api/sync/words/import { locale, source: "swiftkey", words: [string] (≤50000) } → { added, skipped }

GET    /api/backups                    → [{ id, createdAt, deviceName, kind, sizeBytes }]
POST   /api/backups (application/zip body, headers X-Device-Id, X-Device-Name, X-Backup-Kind) → { id }
GET    /api/backups/:id                → the zip
DELETE /api/backups/:id
```
- Never log words or settings values. Usage logs keep counts only.
- Web app: **Words** page (count by source/locale, search, remove = tombstone, add manual) and **Backups** page
  (list, download, delete). Settings stay phone-edited; the web shows when they were last synced.

## Seeding

After deploy, the orchestrator imports Hammas's SwiftKey vocabulary (already cleaned: 17,164 words, kept
privately on hammas-dev at `~/.config/kudkeys/swiftkey-words.combined`) with
`POST /api/sync/words/import` — never commit those words to this public repo, not even as test fixtures (use
made-up words in tests).

## Out of scope

Multi-user sharing, end-to-end encryption, syncing the voice draft.
