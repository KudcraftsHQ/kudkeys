# Kud Keys v0.3 — full voice mode, ✦ Fix, Instruct

Shared contract for v0.3. Read `docs/v0.1-spec.md` for the working rules (they still apply), `server/README.md`
for the backend, `android/NOTES.md` for the app.

## What v0.3 is

1. **Full voice mode.** A short **tap** on Mic (today: "Hold to talk" hint) opens the dictation editor, which
   **replaces the key area** (same height; the top bar stays). Hold-to-talk quick mode is unchanged.
   - Recording starts immediately. The editor shows the full dictated text live (finals as they come, the
     current partial dimmed), a timer, and a large stop button in the Mic's spot.
   - **Stop → tidy (default on):** the text is sent to `POST /api/text/tidy` and comes back as clean prose:
     punctuation, paragraphs, and numbered or bulleted lists where the speaker clearly listed things. Words
     are not changed except obvious mis-hearings; Indonesian slang stays slang (no formalising "nggak" →
     "tidak").
   - **Tidy toggle:** an icon-only toggle, always visible in the editor's top-right. Off = stop keeps the raw
     text. Remembered between sessions.
   - **Raw** shows the untidied text (toggle back to tidied). **Undo** steps back through edits.
   - **Questions:** words the model is unsure about come back as questions; show **one card at a time** above
     the text ("Did you say *Fenno* or *Feno*?", 2–3 options + "keep as is"). Answering replaces the word and
     shows the next card. The card can be dismissed.
   - **Spoken edits (Instruct in the editor):** hold the editor's Instruct button and say an edit ("make the
     second point shorter", "jadikan list bernomor", "hapus kalimat terakhir"); it goes to
     `POST /api/text/instruct` with the current editor text; the result replaces the text (Undo restores).
   - **Tap to continue dictating:** a mic button in the editor appends more dictation to the draft.
   - **Insert** puts the text into the field and closes the editor. **Close (×)** keeps the draft.
   - **The draft survives** leaving the app, switching fields, or the keyboard closing (stored on the phone,
     app-private, excluded from backup). While a draft exists, the Mic shows a small dot; tapping Mic reopens
     the editor with it. Insert or an explicit "Discard" clears it.
2. **✦ Fix** (top bar, left). Fixes the text in the current field: the selection if there is one, otherwise
   the whole field text (via `InputConnection`, up to 4,000 chars around the cursor). Typos, missing
   punctuation, capitalisation; keep the language mix, slang and meaning. The result replaces the text in
   place; the bar shows "Fixed · Undo" for 10 s. Nothing to fix → "Looks good".
3. **Instruct** (top bar, right of centre). Hold to speak an instruction (uses the quick-voice recorder, no
   insert); on release the instruction + the field text (selection or whole field, as Fix) go to
   `POST /api/text/instruct`; the result replaces the text with "Done · Undo". With an empty field the
   instruction is treated as "write this" (e.g. "write a polite reply saying I'll be 10 minutes late").
4. **Privacy.** Text is only sent when Hammas taps Fix/Instruct/tidy (explicit). The server never logs or
   stores text; it records usage rows with counts only (kind, chars in/out, ms). In a private field Fix and
   Instruct still work (explicit action) but the request carries `private: true` and no usage row stores
   anything beyond the kind and timing.

## Server contract (all require `Authorization: Bearer <session token>`; legacy static tokens are refused here)

```
POST /api/text/tidy
  { "text": string (≤20000), "segments"?: [{ "text": string, "confidence"?: number }],
    "languages"?: ["id","en"], "private"?: boolean }
→ { "text": string, "questions": [{ "id": string, "original": string, "start": number, "end": number,
                                    "options": [string] }] }
  start/end are char offsets into the returned text.

POST /api/text/fix
  { "text": string (≤4000), "languages"?: [...], "private"?: boolean }
→ { "text": string, "changed": boolean }

POST /api/text/instruct
  { "instruction": string (≤2000), "text": string (≤20000, may be empty), "languages"?: [...],
    "private"?: boolean }
→ { "text": string }

Errors: 400 bad input, 401 no/invalid session, 429 rate limited (Retry-After), 503 model unavailable.
```

- Model: Groq chat completions on the existing `GROQ_API_KEY` (OpenAI-compatible
  `https://api.groq.com/openai/v1/chat/completions`). `KUDKEYS_TEXT_MODEL` picks the model; evaluate
  `openai/gpt-oss-120b` and `moonshotai/kimi-k2-instruct` (or Groq's current best equivalents) on the
  fixtures below and default to the better one. JSON output (response_format json_object) validated with zod;
  one retry on invalid JSON.
- The profile's `voiceKeywords` and `languages` go into every prompt (spelling of names).
- Fixtures (commit them under `server/test/fixtures/text/`): a long Indonesian–English ramble with a spoken
  list ("pertama… kedua… terus yang ketiga"), a message with typos, slang that must stay slang, a name
  misheard ("Feno" → keyword "Fenno"), an instruction in Indonesian, one in English.

## Out of scope for v0.3

Learning from corrections, clipboard, swipe typing, sending audio anywhere but the voice server.
